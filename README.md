# 1ScURL — внешняя компонента cURL для 1С:Предприятие 7.7

Внешняя компонента (нативная, VK-стиль для 1С 7.7) — обёртка над libcurl:
HTTP/HTTPS, FTP, SMTP и т.д. из встроенного языка 1С 7.7.

## Структура проекта

| Каталог | Назначение | В git |
|---|---|---|
| `curl1c/` | Исходники компоненты (собственно проект) | да |
| `_1Common/` | Общие исходники/заголовки для нативных компонент 1С 7.7 | да |
| `openssl-3.2.1/` | Исходники зависимости (TLS) | да (без артефактов) |
| `curl-8.6.0/` | Исходники libcurl | да (без артефактов) |
| `libssh2-1.11.0/` | Исходники libssh2 | да (без артефактов) |
| `zlib-1.3/` | Исходники zlib (сжатие) | да (без артефактов) |
| `brotli-1.1.0/` | Исходники brotli (сжатие) | да (без артефактов) |
| `Build/` | Промежуточные объектные файлы сборки | **нет** (`.gitignore`) |
| `Release/` | Готовый `curl1c.dll` и собранные `*.lib` зависимостей | **нет** (см. «Релизы») |

Скомпилированные файлы (`*.obj`, `*.lib`, `*.dll`, `*.pdb`, …) в git не попадают —
см. `.gitignore`.

## Сжатие исходящих данных (gzip/deflate) — с версии 17

Компонента умеет сжимать тело HTTP-запроса на лету средствами zlib
(настоящий gzip-поток RFC 1952 / deflate RFC 1950) и сама выставляет
заголовок `Content-Encoding`.

**Автосжатие тела из переменной** (`CompressBody`):

```1c
Карлик.Источник.Данные = БольшойJSON;
Карлик.CompressBody("gzip");        // "gzip" | "deflate" | "none"
Карлик.УстановитьПараметр("URL", "https://сайт/api");
Карлик.Выполнить();                 // тело сожмётся, Content-Encoding: gzip добавится сам
```

**Сжатие файла на диске** (`CompressFile`) — для больших файлов, память не расходуется:

```1c
Карлик.CompressFile(ИсходныйJSON, "c:\tmp\data.gz", "gzip");
Карлик.Источник.Тип    = 1;         // Файл (бинарно-безопасная загрузка)
Карлик.Источник.Данные = "c:\tmp\data.gz";
Карлик.УстановитьПараметр("HTTPHEADER", "Content-Encoding: gzip");
Карлик.Выполнить();
```

Важно: принимающий сервер должен уметь распаковывать сжатое тело запроса
(`Content-Encoding`), иначе получит нечитаемые данные — это по умолчанию
включено не везде, согласуйте с приёмной стороной.

## Сборка

Проект компоненты — `curl1c/1ScURL.cbp` (Code::Blocks). Зависимости собираются
в статические `*.lib`, компонента линкуется в `Release/curl1c.dll`.

## Релизы

Каталог `Release/` в git **не** версионируется. Готовые сборки публикуются
отдельно, каждый релиз — отдельным файлом с номером версии, например:

```
curl1c-v16.dll
curl1c-v17.dll
```

Это позволяет хранить готовые файлы разных релизов «на всякий случай» и при
необходимости выкладывать их в облако независимо от истории исходников.
